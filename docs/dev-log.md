## 配置页面的问题（重要记录）

配置页面在开发过程中经历了多次迭代和问题：
1. 多页菜单架构（v5.0）— JS 压缩过狠导致页面空白
2. 尝试修复双 `<script>` 标签问题 — 多次上传未果
3. 配置页面进不去 → 最终结论：服务器上的文件一直没有被成功更新
4. 当前状态：GitHub 仓库已回退到稳定版本，配置页需要重新整理后重新部署

经验教训：*应该每次上传后验证服务器上的文件 hash，而不是假设上传成功。*

## 第4天 2026-07-26~27：修复与重构

另一台 Claude 直接在服务器上篡改了 server.py（v5.1），加了密码保护 + Function Calling，但砍掉了多页配置页。本地上仍是 v5.0，两边不一致。

启动新一轮修复：

### 合并两版 (v5.3)
- v5.0 的完整多页配置页 + v5.1 的密码保护/Function Calling/文件管理
- Edge TTS 参数格式修复：`"1.0"` → `"+0%"`
- `/files` 页面加 ESC 返回
- 火山引擎 AppID/Token 移入网页配置（API密钥页内 ASR 卡片）
- 配置保存 API 修复：`d:dict` → `d: dict = Body(...)`

### 表情页面彻底重写（踩坑记录）
- 第一次：直接在 PAGES.emotion 模板内嵌 `<script>` + 模板字面量 → 页面白屏
- 第二次：JS 移到主 JS 区，但引号嵌套 `onclick="setFE('k')"` → `Unexpected string` 页面蓝屏
- 第三次：改用 `data-` 属性 + 事件委托，彻底规避引号嵌套问题 ✅
- 最终：可点击设固定表情、弹出选择器自定义表情符号、一键回到自动识别

### 经验教训
1. AI 修改代码要注意**整体架构**，不要只改局部
2. GitHub raw 在国内不稳定，`scp` 上传比 `wget` 可靠
3. `</script>` 不能写在 `<script>` 标签内的任何地方（包括 JS 字符串/模板字面量）
4. HTML onclick 内嵌引号+拼接字符串是最容易出问题的地方，优先用 `data-` 属性+事件委托
